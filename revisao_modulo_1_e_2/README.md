## Exercícios de Revisão – Módulos 1 e 2

### MÓDULO 1 – Introdução à Engenharia de Requisitos

#### 1. Introdução à Engenharia de Requisitos
1. Segundo a norma IEEE 610.12-1990, a Engenharia de Requisitos é:  
a) O processo de codificar funcionalidades em linguagens de programação.  
b) A disciplina de identificar e documentar funções e restrições de sistemas de software.  
c) A técnica de construir protótipos antes da implementação.  
d) A prática de validar requisitos por meio de testes de usabilidade.  
e) O modelo de desenvolvimento em cascata.

2. Qual das opções **NÃO** é uma importância da Engenharia de Requisitos?  
a) Reduzir retrabalho.  
b) Alinhar expectativas entre cliente e equipe.  
c) Servir de base para testes.  
d) Garantir o sucesso de todas as fases automaticamente.  
e) Contribuir para a qualidade final do software.

3. Qual fase do ciclo de vida do software é diretamente suportada pelos requisitos?
a) Testes – servem de base para verificar se o sistema atende ao que foi especificado.
b) Implementação – os requisitos substituem a programação.
c) Análise – elimina a necessidade de entender as necessidades dos usuários.
d) Projeto – torna irrelevantes as restrições técnicas.
e) Manutenção – impede que ocorram mudanças futuras.

#### 2. Princípios da Comunicação
4. Qual princípio de comunicação se refere a **ouvir com atenção antes de responder**?  
a) Clareza e objetividade.  
b) Escuta ativa.  
c) Feedback constante.  
d) Formalização.  
e) Transparência.

5. O requisito “O sistema deve ser rápido ao processar pedidos” é considerado problemático porque:  
a) É muito detalhado.  
b) É ambíguo, não define claramente o que significa “rápido”.  
c) É um requisito funcional.  
d) Está escrito em linguagem estruturada.  
e) Está relacionado apenas ao hardware.

6. Qual das opções **NÃO** é um princípio de boa comunicação em requisitos?  
a) Clareza e objetividade.  
b) Escuta ativa.  
c) Evitar ruídos.  
d) Feedback estruturado.  
e) Uso de jargões técnicos complexos.

#### 3. Conceitos e Classificações de Requisitos
7. O requisito “O sistema deve emitir nota fiscal conforme a legislação brasileira” é classificado como:  
a) Funcional.  
b) Não funcional.  
c) De usuário.  
d) De domínio.  
e) De sistema.

8. Qual das alternativas melhor diferencia **requisito de usuário** de **requisito de sistema**?  
a) Usuário é escrito em linguagem natural; sistema é detalhado e técnico.  
b) Usuário é validado por testes; sistema é apenas teórico.  
c) Usuário descreve restrições; sistema descreve interfaces gráficas.  
d) Usuário é não funcional; sistema é funcional.  
e) Usuário é sempre mais importante que sistema.

9. Qual alternativa representa corretamente um **requisito não funcional**?  
a) O sistema deve permitir cadastrar novos usuários.  
b) O sistema deve enviar e-mail de confirmação.  
c) O sistema deve permitir agendamento de consultas.  
d) O tempo de resposta da tela deve ser inferior a 3 segundos.  
e) O sistema deve exibir relatórios para o gestor.

10. Em um sistema de e-commerce, qual requisito abaixo é **funcional**?  
a) O tempo de carregamento deve ser < 2 segundos.  
b) O sistema deve seguir a legislação de boletos bancários.  
c) O sistema deve permitir que o usuário adicione e remova produtos do carrinho de compras.  
d) A interface deve estar disponível em inglês e português.  
e) O sistema deve suportar até 1000 usuários simultâneos.

### MÓDULO 2 – Processos e Modelos de Requisitos

#### 1. Modelos Preditivos

a) Flexibilidade para mudanças.  
b) Documentação robusta para auditoria.  
c) Baixo risco em ambientes instáveis.  
d) Pouca necessidade de requisitos iniciais.  
e) Entregas incrementais frequentes.

15. Qual é uma **limitação** do modelo preditivo?  
a) Entregas incrementais.  
b) Documentação robusta.  
c) Pouca flexibilidade para mudanças.  
d) Feedback constante do usuário.  
e) Adaptação rápida.

#### 2. Modelos Ágeis
16. Em metodologias ágeis, os requisitos são representados principalmente como:  
a) Diagramas de sequência.  
b) Casos de uso textuais.  
c) User stories.  
d) Especificações formais no início.  
e) Regras de negócio em linguagem legal.

17. Qual dos valores abaixo **faz parte do Manifesto Ágil**?  
a) Processos e ferramentas acima de indivíduos e interações.  
b) Documentação abrangente acima de software em funcionamento.  
c) Colaboração com o cliente acima de negociação de contratos.  
d) Seguir um plano acima de responder a mudanças.  
e) Regras rígidas acima de flexibilidade.

#### 3. User Stories e Critérios de Aceitação
18. Uma boa **user story** deve ser escrita no formato:  
a) O sistema deve realizar X para Y.  
b) Se X acontecer, então Y deve ser exibido.  
c) Como [usuário], quero [funcionalidade], para [benefício].  
d) O usuário deve realizar X obrigatoriamente.  
e) O requisito deve estar em linguagem técnica.

19. No checklist INVEST, o “T” significa:  
a) Temporal.  
b) Técnico.  
c) Testável.  
d) Transparente.  
e) Tolerável.

20. O requisito preditivo “O sistema deve permitir login com e-mail e senha” pode ser reescrito como user story:  
a) O sistema deve validar credenciais.  
b) Como usuário, quero fazer login com e-mail e senha, para acessar minha conta.  
c) O sistema deve ter campos de e-mail e senha obrigatórios.  
d) O sistema deve armazenar todas as credenciais em texto puro.  
e) O usuário deve ter senha com no mínimo 8 caracteres.
